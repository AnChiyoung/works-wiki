# 작업 목록: 위키 핵심 기능 (001-wiki-core)

- 기준: [spec.md](spec.md) · [syntax.md](syntax.md) · [plan.md](plan.md)
- 현재 단계: **M2 마무리 → M3 — 이력·차이·되돌리기, 편집 충돌** (M1 완료)
- 다음 단계 작업은 앞 단계 완료 점검 때 이 문서에 추가한다. (M1 완료, M2 마무리 중)

## 작업 규칙
- 작업은 번호 순서대로 진행한다. `[P]` 표시가 있는 작업은 앞 작업이 끝났다면 서로 동시에 진행해도 된다(다른 파일을 다룸).
- 각 작업의 **완료 조건**을 모두 만족해야 체크한다. 테스트가 있는 작업은 테스트를 먼저 쓰고(실패 확인) 구현한다.
- 작업 중 스펙과 다른 결정이 필요하면 코드를 고치기 전에 스펙을 먼저 고친다. ([원칙 1](../constitution.md))
- 작업 하나가 끝날 때마다 커밋한다. 커밋 메시지에 작업 번호를 넣는다. (예: `T013 문서 저장 서비스`)

## M1 범위

| 포함 | 제외 (다음 단계) |
|---|---|
| 문서 보기, 없는 문서 화면, 대문 이동 | 로그인·권한 (M2) |
| 문서 만들기·편집, 편집 요약, 미리보기 | 이력·차이·되돌리기·편집 충돌 (M3) |
| 마크다운 기본 문법, HTML 정화 | 위키 링크·분류·각주·색·접기 상자·코드 강조 (M4) |
| 제목 자동 번호·목차·문단 접기, 목록 깊이 양식 | 검색·최근 변경 (M4) |
| 리비전 저장 (덮어쓰지 않음) | 이동·파일 (M5), 관리 (M6) |

**M1 임시 규칙**: 로그인이 없으므로 서버는 이 PC(127.0.0.1)에서만 접속되게 띄우고, 환경 변수 `WIKI_OPEN_EDIT=true`일 때만 편집을 허용한다. 편집자는 내장 `system` 사용자로 기록한다. M2에서 이 규칙을 없애고 관리자 로그인으로 바꾼다. → **T035에서 제거됨.**

# M2 — 관리자 로그인과 권한

## M2 범위

| 포함 | 제외 (다음 단계) |
|---|---|
| 첫 관리자 생성 명령어 | 가입 신청, 회원 승인·차단 화면 (M6+) |

  - `/diff/:title?from=&to=`: 두 판의 차이를 위아래 한 줄 형식으로 보여준다(휴대폰에서도 읽히게). 추가는 초록, 삭제는 빨강, 줄 앞에 `+`·`-` 표시(색을 못 보는 사람도 구분되게).
  - `from`이 없으면 바로 앞 판과 비교. 잘못된 판 번호는 404.
  - 완료 조건: 화면 테스트로 차이 표시가 확인된다.

## 12단계: 되돌리기와 충돌

- [ ] **T044 되돌리기 서비스** — AC-4.4
  - `revertPage(db, { fullTitle, toRevNo, authorId, baseRevId })`: 과거 판의 내용으로 새 리비전을 만든다. 종류 `revert`, 요약 "N판으로 되돌림"(사용자가 적은 요약이 있으면 뒤에 붙임).
  - 최신 판과 내용이 같으면 저장하지 않는다. 권한은 `edit`(`can()`).
  - 테스트: 새 판 생성, 내용 일치, 이미 같은 내용, 없는 판.
  - 완료 조건: 위 테스트 통과.

- [ ] **T045 되돌리기 화면** — AC-4.4
  - 과거 판 화면에 "이 판으로 되돌리기" 버튼(권한 있는 사람에게만). 누르면 확인 창 → 서버 액션 → 문서 보기로 이동.
  - 서버 액션도 `can()`으로 다시 확인한다.
  - 완료 조건: 화면 테스트로 되돌리기 후 이력에 `revert` 판이 생기는 것을 확인.

- [ ] **T046 편집 충돌** — AC-2.5
  - `savePage`: 트랜잭션 안에서 `baseRevId`가 최신 판과 다르면 저장하지 않고 `ConflictError`(최신 판 정보 포함). 새 문서를 동시에 만든 경우도 충돌로 본다.
  - 편집 화면: 충돌이 나면 "다른 사람이 먼저 저장했습니다" 안내와 함께 최신 판과 내 내용의 차이를 보여주고, 내가 쓴 내용은 입력창에 그대로 둔다. 최신 판 기준으로 다시 저장할 수 있게 `baseRevId`를 최신으로 바꾼다.
  - 되돌리기도 같은 방식으로 충돌을 검사한다.
  - 테스트: 단위(충돌 감지, 동시 생성) + 화면(탭 두 개로 같은 문서를 고쳐 충돌 화면 확인).
  - 완료 조건: 위 테스트 통과.
