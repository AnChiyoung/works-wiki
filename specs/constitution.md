# 프로젝트 원칙 (Constitution)

모든 스펙·설계·코드는 이 원칙을 따른다. 원칙과 충돌하는 결정이 필요하면 코드보다 이 문서를 먼저 고친다.

## 1. 스펙이 먼저다
- 기능은 `spec.md`(무엇을, 왜) → `plan.md`(어떻게) → `tasks.md`(작업 단위) → 코드 순서로 만든다.
- 동작을 바꾸려면 스펙을 먼저 고치고, 코드를 그에 맞춘다.
- 스펙의 모든 수용 기준(Acceptance Criteria)은 자동화 테스트로 검증할 수 있어야 한다.

## 2. 열람은 공개, 편집은 관리자 중심
- 로그인하지 않은 방문자도 모든 공개 문서를 읽고 검색할 수 있다.
- 기본적으로 편집은 관리자(위키 운영자)만 한다.
- 다른 회원은 관리자가 승인한 기능만, 기능별로 따로 쓸 수 있다. 기본 권한은 없다.
- 권한 검사는 항상 서버에서 한다. 화면에서 버튼을 숨기는 것만으로는 권한 검사가 아니다.

## 3. 모든 변경은 기록되고 되돌릴 수 있다
- 문서 편집은 덮어쓰지 않고 새 리비전(판)으로 쌓는다.
- 삭제도 "삭제 상태"로 표시할 뿐, 이력은 남긴다.
- 관리 행위(권한 변경, 차단, 보호, 삭제)는 감사 로그에 남긴다.

## 4. 단순함 우선
- 한 대의 서버(개인 PC 포함)에서 돌아가야 한다. 별도 DB 서버 없이 SQLite를 기본으로 한다.
- 필요해지기 전에는 캐시 서버, 메시지 큐, 마이크로서비스를 도입하지 않는다.
- 외부 의존성은 꼭 필요한 것만 쓴다.

## 5. 보안 기본값
- 비밀번호는 argon2id로 해시하고, 원문은 어디에도 저장·기록하지 않는다.
- 사용자가 입력한 문서 내용은 렌더링할 때 반드시 정화(sanitize)해 XSS를 막는다.
- 상태를 바꾸는 요청(POST 등)에는 CSRF 보호를 적용한다.
- 로그인·가입 요청에는 횟수 제한(rate limit)을 둔다.

## 6. 한국어 우선, 누구나 읽기 쉽게
- 화면 문구, 문서 제목, URL은 한국어를 기본으로 지원한다.
- 모바일에서도 읽고 편집할 수 있어야 한다.
- 검색엔진이 문서를 읽을 수 있도록 서버에서 HTML을 렌더링한다.

## 7. 데이터는 사용자의 것
- 데이터는 백업하기 쉬운 형태(SQLite 파일 + 업로드 폴더)로 보관한다.
- 문서 원문은 언제든 내보낼 수 있어야 한다.
